# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A single-file static web app (`index.html`) that ranks U.S. states and U.S. places by the dollar tax burden a wealthy person would face moving there for retirement. No build system, no package.json, no tests, no dependencies. Open the file in a browser; that's the whole thing.

## Commands

- **Run the app**: `open index.html` (no server needed; everything is inline)
- **Regenerate the places dataset**: `node scripts/fetch_places.mjs > /tmp/places.js` — one-off acquisition that hits the U.S. Census ACS 5-year API 51 times (one per state + DC), filters to places with population ≥ 5,000, sorts by % Asian Indian, takes the top 200. Output is meant to be pasted into `index.html` as the `PLACES` const, **not** loaded at runtime. The Census API is unkeyed (rate-limited at 500 req/day per IP).
- **Sanity-check JS after edits**: `node -e "const m = require('fs').readFileSync('index.html','utf8').match(/<script>([\s\S]*?)<\/script>/); new Function(m[1]); console.log('OK')"`

## Architecture

All logic lives inside one `<script>` block in `index.html`. The shape that matters:

**Three parallel data structures, all keyed by state name**, must stay in sync when adding or modifying states:
1. `STATES` array — each entry has `name`, `type` (`"free" | "estate" | "inheritance"`), and a `calc(estate, heir, marital)` function returning `{tax, breakdown, calc}`. This is the state estate/inheritance tax engine.
2. `TAX_RATES` object — `{income, capGains, note?}` per state. Note: keyed by canonical state name (no "(Estate)"/"(Inheritance)" suffix); `ratesFor()` strips the suffix before lookup.
3. `PLACES` array — 200 entries `{name, state, population, pctIndian}`. The `state` field must match a `TAX_RATES` key exactly. Generated by `scripts/fetch_places.mjs`.

**Hardcoded scenario assumptions** baked into `computeAll(estate)`:
- Heir = `"lineal"` (children/grandchildren)
- Marital deduction = `false` (this is the *second* death; surviving spouse already gone)

This is why all 6 inheritance-tax states (KY, MD-Inheritance, NE, NJ, PA, and Iowa-as-repealed) currently show $0 — children are Class A everywhere. Changing these defaults requires editing `computeAll()`, not state calc functions.

**Maryland is special**: it appears as two entries (`"Maryland (Estate)"` and `"Maryland (Inheritance)"`). When the places table maps places to a state's total, those two rows must be **summed on `.tax` only** — `incomeTax` and `capGainsTax` are identical across both rows (`ratesFor` strips the suffix) and would double-count. See the `stateByName` build in `render()`.

**Federal credit table** (`creditTable()`) implements the 1999 federal state-death-tax-credit schedule, still used by IL, MA, and RI for their bracket math. Don't try to "modernize" this — those state statutes literally reference the 1999 federal table.

**Tax-law currency**: encoded as of mid-2026. Key non-obvious facts:
- Washington uses the **post-July 2026 regime** under SB 6347 (10%–20% rates, $3M exemption frozen). The SB 5813 35% top rate was a one-year experiment ending June 30, 2026.
- Connecticut conforms to the federal $15M exemption (OBBBA permanent, Jan 2026).
- WA millionaires' tax (SB 6346, 9.9% on AGI > $1M) is effective **Jan 2028** — currently reflected only in the WA capgains cell (9.9%, includes the surcharge) and as a footnote in the income column's expanded detail.

**Rendering is fully reactive**: any input change calls `render()`, which recomputes everything and rewrites both tables' innerHTML. Sort state lives in module-scope vars (`sortBy`/`sortDir` for states; `placesSortBy`/`placesSortDir` for places). Click-to-expand state lives in `expandedState` / `expandedPlace`.

**No CSS framework, no JS framework, no bundler**. Just vanilla DOM + a Google Fonts link for Inter. CSS uses CSS custom properties for the palette (`--ink`, `--accent`, etc.) defined in `:root`.
