# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A static web app — title **"Where should I move?"** — that ranks U.S. places by total tax cost (estate + income + cap gains over a chosen horizon) and lets the user filter by demographics, political lean, household income, education, wealth concentration, home value, and population. No build system, no package.json, no tests, no dependencies. Open `index.html` in a browser; that's the whole thing.

Two source files now make up the app:
- `index.html` — the app: markup, CSS, and inline JS (tax engine + interaction).
- `data/places.js` — the dataset (~1.7 MB), auto-generated; do not hand-edit. Declares **two** top-level globals loaded by `index.html` via `<script src="data/places.js"></script>` **before** the inline app script: `const PLACES = [...]` (~8,036 place rows) and `const STATE_ROWS = [...]` (51 state/DC rows, same field schema — the macro granularity level).

The page is **one table with a two-level granularity switch** — a `[ Places | States ]` tab control (folder tabs sitting atop the table card; the per-level controls — search, preset filters, columns — live in a toolbar strip below the tabs) swaps which array the table renders (`granularity` = `'places' | 'states'`). Both arrays share the identical field schema, so the entire render/sort/filter/search pipeline is reused; only the source array and a few level-specific behaviors change. (A separate states-only table existed even earlier and was removed; this re-introduces the state level *inside* the same table rather than as a parallel one.) At the **States** level, four columns that carry no meaning there are force-hidden (`metro`, `state`, `janTempF`, `julTempF` — see `LEVEL_HIDDEN`), the identity column relabels "Place"→"State", and **rows become clickable to drill** into that state's places (sets `drillState`, switches to Places filtered to that state, shows a removable breadcrumb in the subtitle). Tax columns are exact at the state level (the engine is per-state). The table is **virtually scrolled** — it presents as one continuous list of the full filtered/sorted set, but only the ~40 rows near the viewport are in the DOM at any time (see Rendering, below). A **search box** in the column-filter row matches free text against place / state / metro names (browser ctrl-F can't see un-rendered rows). **Horizontally scrollable** when the viewport is narrower than the sum of column widths; `min-width` on the grid rows (computed from `COL_DEFS`) keeps columns from being squeezed.

## Working style

Don't test or verify changes proactively. The user does manual testing in their own browser. Do not spin up a local web server, do not use Playwright/MCP browser tools, do not screenshot, and do not exercise filters/sorts/UI flows after editing — even to "sanity-check" the change. Make the edit, optionally run the JS-parse sanity-check below if non-trivial JS changed, and stop. Only run any kind of verification (dev server, browser, end-to-end clicks) when the user explicitly asks.

## Commands

- **Run the app**: `open index.html` (no server needed — `<script src="data/places.js">` works under `file://` because the data file is plain JS, not JSON-via-fetch).
- **Regenerate the places dataset**: `node scripts/fetch_places.mjs` — one-off acquisition. The script writes directly to `data/places.js` (no shell redirect, no splicer). Hits the Census ACS 5-year API 51 times (one per state + DC) plus the 12 strong-MCD states for county subdivisions; fetches a place-to-county crosswalk from the Census Bureau; fetches MIT/MEDSL's 2024 county presidential margin via the `tonmcg/US_County_Level_Election_Results_08-24` GitHub mirror; fetches the 2023 Census Gazetteer (places + cousubs zips) for `ALAND_SQMI` — the population-density denominator — and for `INTPTLAT`/`INTPTLONG`, each place's interior-point coordinate; fetches NOAA's 1991–2020 U.S. Climate Normals (a station inventory plus a monthly-temperature `.tar.gz`, no API key, no rate limits) and matches each place to its nearest station for January/July mean temperature. Pulls these ACS variables per place: `B02018_021E` (Asian Indian), `B02011_001E` (total Asian), `B01003_001E` (population), `B19013_001E` (median HHI), `B19013D_001E` (median HHI, Asian-alone householder), `B25077_001E` (median home value), `B15003_001/022/023/024/025E` (educational attainment, for the bachelor's+ rollup), `B19001_001E`/`B19001_017E` (households at $200k+), `B05012_001E`/`B05012_003E` (foreign-born share), `B03002_001/003/004/012E` (race/ethnicity shares — Hispanic, non-Hispanic Black, non-Hispanic White), `B17001_001E`/`B17001_002E` (poverty rate), `B01002_001E` (median age), `B25003_001E`/`B25003_002E` (homeownership). Requires `CENSUS_API_KEY` — set it in `.env` (gitignored) or export it; sign up at https://api.census.gov/data/key_signup.html. The Gazetteer fetch shells out to `unzip`, and the NOAA temperature archive to `tar` (both preinstalled on macOS/Linux). Also fetches the 2025 County Health Rankings analytic CSV for county homicide rates (NCHS, measure `v015`). **State rows** (`STATE_ROWS`) are built in the same run: one extra ACS call (`for=state:*`) for true state demographics/medians, plus state aggregates produced alongside the county maps in the same loaders — vote-weighted `demMargin`, exposure-weighted FEMA (health by population, property by building value), the direct NCHS state homicide row (CHR `countycode==000`), and state land area summed from the counties Gazetteer (added to the Gazetteer fetch). The ACS row parsing is shared by places/cousubs/states via the `acsDemographics(row)` helper. After regen, verify the file ends with `~8,036 places + 51 states`.
- **Sanity-check JS after edits**: `node -e "const m = require('fs').readFileSync('index.html','utf8').match(/<script>([\s\S]*?)<\/script>/g); new Function(m[m.length-1].replace(/^<script>|<\/script>$/g, '')); console.log('OK')"` (the regex grabs the **last** `<script>` block — the inline app script — since the file now has two: the data-loading `<script src>` and the inline app code).

## Architecture

All logic lives in one `<script>` block in `index.html`. The data flow:

**Three parallel tax data structures, all keyed by state name**, must stay in sync when modifying states:
1. `STATES` array — each entry has `name`, `type` (`"free" | "estate" | "inheritance"`), and a `calc(estate, heir, marital)` function returning `{tax, breakdown, calc}`. The state estate/inheritance tax engine.
2. `TAX_RATES` object — `{income, capGains, note?}` per canonical state name. `ratesFor()` strips any `(Estate)`/`(Inheritance)` suffix before lookup.
3. `PLACES` array — ~**8,036 entries**, each shaped `{name, state, metro, population, pctIndian, pctAsian, medianHHI, medianHomeValue, pctBach, pct200k, pctForeignBorn, pctHispanic, pctBlack, pctWhite, pctPoverty, medianAge, pctHomeowner, asianMedianHHI, popDensity, demMargin, femaHealthRate, femaHealthPct, femaHealthHazards, femaPropRate, femaPropPct, femaPropHazards, janTempF, julTempF}`. Lives in `data/places.js` as a top-level `const PLACES = [...]`; loaded into the global scope before the inline app script runs. The `state` field must match a `TAX_RATES` key exactly. The `metro` field is `null` for ~9 places in less-populous CBSAs; ACS-suppressed values (HHI, home value, asianMedianHHI for small Asian populations, etc.) are `null`. `pctHispanic`/`pctBlack`/`pctWhite` are mutually-exclusive race/ethnicity shares from Census table B03002 (Hispanic of any race; non-Hispanic Black/White alone); `pctPoverty` is the share below the federal poverty line. `janTempF`/`julTempF` are the January/July mean temperature (°F) from the nearest NOAA 1991–2020 climate-normal station — `null` only when the place has no Gazetteer coordinate. FEMA National Risk Index gives two size-independent hazard *rate* streams (deliberately the rates, not the headline composite Risk Index which scales with county population/value): **health** — `femaHealthRate` is modeled expected-annual population loss (fatalities + injuries) per 100k residents/yr (a relative index, not an observed death rate — it annualizes rare catastrophic events); **property** — `femaPropRate` is expected-annual building loss per $100k of value. Each has a national percentile (`femaHealthPct`/`femaPropPct`, used only for cell color) and a comma-joined top-3 hazard-driver string (`femaHealthHazards`/`femaPropHazards`, `"Name (Rating)"`, shown as a hover title). The Health risk column is primary; Property risk is a separate default-hidden column. The cells display each rate as a **multiple of the dataset median** ("× typical", 1.0× = the median place) — the raw rates are small, clustered, unanchored numbers; the median is computed once in the inline script (`FEMA_HEALTH_MEDIAN`/`FEMA_PROP_MEDIAN`), so this is display-only and needs no regen. Sorting uses the raw rate (order-preserving); filtering and the active-filter chips are in × units; the absolute rate is in the cell's hover title. All county-level (joined like `demMargin`) and `null` where FEMA has insufficient data. `homicideRate` is homicide deaths per 100k/yr (county-level, NCHS 2017–2023 via County Health Rankings; `null` when suppressed/<10 deaths). Generated by `scripts/fetch_places.mjs`.

`STATE_ROWS` (51) has the **identical shape**, so the UI renders it through the same pipeline. State values are direct ACS state-level pulls wherever possible (all demographics + **true** medians); the county-joined fields are aggregated to the state in the same loaders — `demMargin` vote-weighted, FEMA exposure-weighted (health by population, property by building value, percentile-ranked within the county distribution for color, top-3 hazards by summed loss), `homicideRate` the direct NCHS state value, `popDensity` = population ÷ summed county land area. `metro`, `janTempF`, `julTempF` are always `null` at the state level (a statewide temperature average is climatologically meaningless — deliberately dropped, not unavailable).

**Hardcoded scenario assumptions** baked into `computeAll(estate)`:
- Heir = `"lineal"` (children/grandchildren)
- Marital deduction = `false` (this is the *second* death; surviving spouse already gone)

This is why all 6 inheritance-tax states (KY, MD-Inheritance, NE, NJ, PA, and Iowa-as-repealed) show death tax of $0 for most places — children are Class A everywhere. (PA is the exception: it has a 4.5% rate on lineal descendants, so PA places show ~4.5% × estate.) Changing these defaults requires editing `computeAll()`, not the state calc functions.

**Maryland is special**: it appears as two entries (`"Maryland (Estate)"` and `"Maryland (Inheritance)"`). When building the `stateByName` lookup for places, those two rows are merged: **only `.tax` is summed**. `incomeTax` and `capGainsTax` are identical across both rows (`ratesFor` strips the suffix) and would double-count.

**Federal credit table** (`creditTable()`) implements the 1999 federal state-death-tax-credit schedule, still used by IL, MA, and RI for their bracket math. The schedule is law-referenced in those state statutes — don't "modernize" it.

**Tax-law currency**, encoded as of mid-2026. Key non-obvious facts:
- Washington uses the **post-July 2026 regime** under SB 6347 (10%–20% rates, $3M exemption frozen). The one-year 35% top rate from SB 5813 expires June 30, 2026.
- Connecticut conforms to the federal $15M exemption (OBBBA permanent, Jan 2026).
- WA millionaires' tax (SB 6346, 9.9% on AGI > $1M) is effective **Jan 2028** — currently reflected only in the WA cap-gains rate (9.9%, includes the surcharge) and as a footnote in the row's expanded detail.

**Granularity caveats baked into specific columns**:
- **`demMargin` is county-level**, applied to every place in the county. Column header says "County red/blue '24" to flag this. Within high-population counties (LA, Cook, Travis, Santa Clara), real intra-county political variation is huge — accuracy is best at the center-of-county level, worst for suburbs of major cities. Sourced from `COUNTY_DEM_MARGIN` map at fetch time via the tonmcg CSV, then attached to each place via the Census Place-to-County crosswalk (`PLACE_TO_COUNTY`).
- **Income/cap-gains rates are state-level only** — local overlays (NYC's 3.876% city tax, Maryland counties' 2.25-3.20%, OH/KY/IN municipal taxes, Yonkers, PA local EIT) are NOT modeled. This **understates** tax for places in those states. The biggest blind spots are NYC boroughs and Maryland counties (Bethesda, Ellicott City, etc.).

**Metro lookup** in the fetch script: `METROS` is a curated map (~50 CBSAs) of `{stateFP: [counties]}` → metro name. Flattened into `COUNTY_TO_METRO` and used during fetch. **Connecticut quirk**: CT switched from counties to Planning Regions in the 2022+ ACS — both the place-to-county crosswalk and the API NAME field use the new region names ("Capitol Planning Region", etc.), and the metro map handles both old county names and new region names.

**Strong-MCD states**: in 12 states (CT, ME, MA, MI, MN, NH, NJ, NY, PA, RI, VT, WI), the primary local government unit is the township/town, not a Census Place. The fetch script queries `county subdivision:*` in addition to `place:*` for these states so entries like Plainsboro Township NJ and Lexington Town MA appear. Deduplication by `(state, cleanName)` keeps the larger-population entry when a township and a same-named CDP collide.

**Rendering** is reactive and virtually scrolled. Any change to the four input fields (years, annual income, annual cap gains, estate at death), to a sort header, to a filter input, to the search box, or to the granularity switch calls `render()`, which (1) picks the source array (`SRC` = `STATE_ROWS` in States view, else `PLACES`), (2) recomputes all tax values for every row in it, (3) filters (including the `drillState` restriction) and sorts the full list into `placeRowsFull`, and (4) sizes the `<ul>` to `rowCount × ROW_H` and calls `paintWindow()`. `paintWindow()` builds innerHTML for **only the rows whose vertical band intersects the viewport** (plus an `OVERSCAN` buffer) — ~40 `<li>` rows — and is also fired (rAF-throttled) on `window` scroll/resize. Rows are absolutely positioned at `top: globalIndex × ROW_H` inside the `position: relative` `<ul>`; each `<li>` carries `data-i` (its global index) so a click can map back to its row. This keeps the DOM bounded so load and per-keystroke re-render stay fast even on mobile. `ROW_H` (44) is the single source of truth for row height and must match the `li.row` CSS height. The search box `input` listener is debounced ~150ms. State: `granularity` / `drillState` / `placesSortBy` / `placesSortDir` / `placesFilters` / `placesSearch` (all reflected in the URL — `g`/`ds` for granularity/drill — and column visibility in `localStorage`). **Rows are non-interactive in Places view; in States view they are clickable to drill** into that state. Column visibility is the effective set for the current level (`computeVisibleCols()` → `renderVisibleCols`, used by both `applyColumnLayout()` and `renderRowHTML()`).

**Column-header tooltips**: every column header carries an `.info-tooltip` span that appears on hover of the header itself (no info button — they were removed to reduce clutter). Tooltips describe the source (Census variable, MIT Election Lab, etc.) and any caveats (county-level margin, state-only tax modeling, etc.). The tooltip is absolutely positioned within the `position: relative` header `[data-sort]` div and is `pointer-events: none`.

**No CSS framework, no JS framework, no bundler**. Vanilla DOM + a Google Fonts link for Inter. CSS uses CSS custom properties for the palette (`--ink`, `--accent`, etc.) defined in `:root`. Table max-width is 1700px; viewport-wrap max-width matches. A `.table-scroll` wrapper inside `.table-shell.places` provides horizontal overflow with `overflow-x: auto`.
